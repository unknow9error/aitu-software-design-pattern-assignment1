# Подготовка к защите

## Основная идея

Builder позволяет собирать объект по шагам. Здесь сначала задаётся заголовок,
затем добавляются разделы, а вызов `build()` создаёт готовый отчёт.
Одинаковые шаги дают два результата: обычный текст и HTML с тегами.

В программе шесть классов:

| Класс | Назначение |
| --- | --- |
| `Report` | Готовый отчёт: заголовок и содержимое. Getters позволяют прочитать эти поля. |
| `ReportBuilder` | Хранит заголовок и накопленные разделы, проверяет данные, задаёт шаги сборки. |
| `PlainTextReportBuilder` | Оформляет разделы и весь отчёт обычным текстом. |
| `HtmlReportBuilder` | Оформляет тот же отчёт с HTML-тегами. |
| `ReportDirector` | Содержит готовый рецепт: заголовок и три раздела. |
| `Main` | Запускает программу, выбирает builders и печатает результаты. |

## Как читать код

**`class`** описывает, какие данные и методы будут у объекта.
Например, у `Report` есть поля `title`, `content` и методы `getTitle()`,
`getContent()`. Через `new` создаётся конкретный объект этого класса.

**`abstract class ReportBuilder`** — общая основа для двух builders.
Создать `new ReportBuilder()` нельзя: способы оформления ещё не определены.
При этом `setTitle()`, `addSection()` и `build()` уже реализованы в этом классе.

**`extends ReportBuilder`** означает наследование. Оба конкретных builders
получают общие методы сборки и добавляют свои способы оформления.

**`@Override`** показывает, что метод реализует или переопределяет метод
родительского класса. Здесь каждый builder реализует `formatSection()`
и `formatReport()`: один добавляет переносы строк, другой — HTML-теги.

**`return this`** возвращает текущий builder. Поэтому после одного вызова
сразу можно вызвать следующий — это fluent API, или цепочка методов:

```java
Report report = new PlainTextReportBuilder()
        .setTitle("My homework")
        .addSection("Task", "Practice method chaining")
        .build();
```

**`new Report(...)`** внутри `build()` создаёт готовый продукт из собранных
данных. `setTitle()` и `addSection()` возвращают builder, а `build()` — уже `Report`.

## Демонстрация за 3 минуты

1. **0:00–0:45.** В корне проекта выполнить `bash scripts/run.sh`.
   Показать обычный текст, HTML и отдельный отчёт без Director в терминале.
2. **0:45–1:30.** Открыть `Main.java` и `ReportDirector.java`.
   Показать: один рецепт вызывается с двумя разными builders.
3. **1:30–2:15.** Открыть `ReportBuilder.java` и конкретные builders.
   Объяснить `return this`, два метода оформления и `new Report(...)`.
4. **2:15–3:00.** Выполнить `bash scripts/test.sh`.
   Ожидаемый итог — `All 5 checks passed`. Показать проверку отсутствующего заголовка.

Пять проверок в `ReportBuilderTest`:

1. Обычный текст содержит нужный заголовок и разделы.
2. HTML содержит нужные теги, экранирует пользовательский текст и закрывает документ.
3. Шаги возвращают тот же builder, а цепочка создаёт ожидаемый отчёт.
4. `build()` без заголовка вызывает ошибку.
5. `build()` без разделов вызывает ошибку.

## Короткие ответы на вопросы

**Зачем Builder, если у `Report` всего два поля?**
Сам объект простой, но его содержимое собирается из нескольких разделов.
На этом примере видны пошаговая сборка и два варианта результата.
Для отчёта с заранее готовым содержимым достаточно обычного конструктора.

**Зачем Director?**
Он сохраняет последовательность шагов, которую можно повторить для обоих форматов.
Он необязателен: в `Main` есть самостоятельная цепочка без него.

**Где проверки данных?**
`checkText()` отклоняет `null`, пустые строки и строки из пробелов.
`build()` требует заголовок и хотя бы один раздел.

**Зачем `escape()` в HTML builder?**
Он заменяет `&`, `<` и `>`, чтобы введённый текст не превратился в HTML-теги.

**Можно повторно использовать builder?**
Да, но `build()` не очищает его разделы. Для нового отчёта в примере создаётся
новый builder. Каждый `build()` возвращает отдельный объект `Report`.
